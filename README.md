# Bet Hub

A personal, phone-friendly dashboard that aggregates the day's recommended bets
from all of your models (bet-screen, golf-modeling, cfb-modeling, DFS ENGINE,
KP_MM, EV_Model, …) and tracks their accuracy and P/L over time.

Your models stay in R and simply drop standardized JSON into a shared feed folder.
A small local uploader validates that JSON and pushes it to a database. The web app
only ever reads the database. The **picks contract** ([`docs/CONTRACT.md`](docs/CONTRACT.md))
is the only interface anyone has to honor — the messy internals of each model stay
fully decoupled from the site.

```
[R models, local] --write--> dashboard_feed/*.json --ingest--> [Postgres/Supabase] <--read-- [Next.js on Vercel] <-- phone
     (unchanged)             (OneDrive-synced)     (local task)     (single store)          (Refresh = re-query)
```

This build is wired end-to-end with **mock data**, so the dashboard runs and looks
real with zero cloud setup. Hooking up each real model is a later, per-folder step
(see `docs/CONTRACT.md`).

## Layout

```
packages/
  contract/   THE interface — Zod schema + TS types + JSON Schema export + examples
  core/       pure math — odds → implied prob, P/L settlement, ROI/CLV rollups
  db/         Drizzle schema, the mock dataset, DB read/write helpers
apps/
  web/        Next.js 15 dashboard — Today / Tracker / Sources, PWA, theme-aware
  ingest/     local uploader — scans the feed folder, validates, upserts to Postgres
docs/
  CONTRACT.md the spec each model follows to feed the dashboard
```

The feed folder lives outside the repo, in OneDrive:
`C:\Users\ljdie\OneDrive\Documents\dashboard_feed\` (override with `FEED_DIR`).

## Prerequisites

- Node ≥ 20 (built on Node 24), pnpm ≥ 9 (built on 11.5)
- Git is **not** required to run locally, but you'll want it installed for the
  Vercel deploy step later.

## Quick start (demo mode — no cloud needed)

```powershell
pnpm install
pnpm web            # http://localhost:3141  (uses the in-memory mock dataset)
```

Open it, tap around Today / Tracker / Sources, hit Refresh. Everything you see is
generated by `packages/db/src/mock.ts`.

## Commands

| Command | What it does |
|---|---|
| `pnpm web` | Run the dashboard (dev). Demo data by default. |
| `pnpm build` | Production build of the web app. |
| `pnpm contract:test` | Validate the example payloads against the contract (+ a negative case). |
| `pnpm contract:schema` | Export JSON Schema to `dashboard_feed/_schema/`. |
| `pnpm contract:examples` | Write the reference example files to `dashboard_feed/_examples/`. |
| `pnpm ingest:dry` | Scan + validate every file in the feed folder; no DB writes. |
| `pnpm ingest` | Validate + upsert the feed into Postgres (needs `DATABASE_URL`). |
| `pnpm seed` | Load the mock dataset into Postgres (needs `DATABASE_URL`). |
| `pnpm --filter @bet/db push` | Push the Drizzle schema to the database. |

## Going live (later)

1. **Supabase**: create a project (free tier). Put its connection string in
   `apps/web/.env.local` and (for ingest) your shell env as `DATABASE_URL`.
2. `pnpm --filter @bet/db push` to create the tables.
3. Point the web app at the DB: set `DATA_SOURCE=supabase` in `apps/web/.env.local`.
4. **Ingest on a schedule**: register `pnpm ingest` as a Windows Scheduled Task
   (same pattern your models already use) so new picks flow up automatically after
   each model run.
5. **Deploy**: push to a Git repo and import into Vercel. Add `DATABASE_URL` +
   `DATA_SOURCE=supabase` as Vercel env vars. Gate the site with Supabase Auth
   (single allowed email) — this is private betting data on a public URL.

## Security

- **Rotate the DataGolf API key** currently sitting in plaintext in
  `golf-modeling\claude\deploy\README_DEPLOY.md`, then move it to env vars.
- The feed folder carries **picks only** — never secrets. DB URLs and any book/API
  keys live in `.env*` (git-ignored), never in the repo or the feed.
- `bet-screen\secrets.env` and `DFS ENGINE\config\dk_session.txt` stay where they
  are; the dashboard never needs them.

## Notes

- The web app runs on hand-written CSS built from a validated data-viz palette
  (theme-aware light/dark) — no Tailwind dependency, so it's robust to build.
- Charts are inline SVG (bankroll line with crosshair tooltip; diverging per-sport
  P/L bars) — no charting library.
